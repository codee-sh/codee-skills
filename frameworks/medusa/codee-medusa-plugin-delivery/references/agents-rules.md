# Plugin rules for AGENTS.md and CODE_REVIEW.md

What a plugin's `AGENTS.md` and `CODE_REVIEW.md` add to the rules every project has. Merge each block into
the matching section of the existing file; replace a rule only where it says the opposite, and leave the
rest of the file as it is. The Skill Router is `agents-templates/medusa-plugin.md` in `codee-skills`.

## AGENTS.md

Open the file by saying what the repository is:

```markdown
It is a plugin, not an application: it runs only inside a Medusa project that installs it, and what it
exports is a public contract other projects build on.
```

### Always

```markdown
- **MUST, on a Medusa version bump,** read the GitHub release page of every release in the range, move every
  `@medusajs/*` dev and peer dependency to the new version together, run the gate and the linked project's
  tests, and prune the lessons per `codee-lessons`, "Pruning".
- **MUST let the user's `yarn dev` carry a change to a linked project.** Do not run `yarn build` while it
  runs: a build removes `.medusa/server`, and with it the link `yarn dev` makes to the Admin source, until
  `yarn dev` starts again. To refresh the declarations the project typechecks against, run
  `npx tsc -p tsconfig.json --emitDeclarationOnly`, then `yalc publish --push --no-scripts`.
```

### Plugin Contract

```markdown
## Plugin Contract

- **The public contract** is <the config types, what the package root and its subpaths export, the
  shapes of the Admin and store routes, the inputs and outputs of the exported workflows, and the events>.
  An additive change is a minor version; anything else is breaking: a major version, stated in its
  changeset and its commit message.
- **Medusa packages** are `devDependencies` at the installed version and `peerDependencies` at the same
  version. Declare nothing Medusa or the dashboard already brings with yarn, such as
  `@tanstack/react-query`, `react-router-dom` or `@medusajs/js-sdk`.
- **The Admin is a browser bundle loaded by the project.** It imports only types from backend code; a
  value import pulls Node code into it.
- **yarn only.** A pnpm command here moves the dependencies aside into `node_modules/.ignored`.
```

### Ask First

```markdown
- **Before committing, merging or creating a branch.** Commit only when the user explicitly asks for it.
- **Before adding a remote or publishing.**
- **Before adding a dependency** of any kind. Check what Medusa and the dashboard already ship.
- **Before changing the public contract** in a way that is not additive.
```

### Never

```markdown
- **Never run `yarn install`, `yarn dev`, `medusa develop`, or another long-running or dependency-install
  command**, here or in a linked project. The user runs them; tell them what to run and what to check.
- **Never create or run migrations.** Schema belongs to the user, the test module's included: its
  migrations come from the user's `yarn test:db:generate`.
- **Never import from a project.** A project depends on the plugin, not the other way round.
```

### Validation Commands

```markdown
| Check | Command |
|------|---------|
| Lint | `yarn lint` |
| Typecheck | `yarn typecheck` |
| Admin typecheck | `yarn typecheck:admin` |
| Format | `yarn format:check` |
| Unit tests | `yarn test:unit` |

- HTTP and workflow integration tests run in the plugin, manually, when a step's verification asks for
  them. The agent may run the whole cycle - `yarn test:db:up`, `yarn test:integration:http` or `:modules`,
  then `yarn test:db:down` for a database it started itself, never for one it found running - and says
  in its report that it did. `yarn test:db:generate` is the user's. How to run and extend them is in
  [docs/tests.md](docs/tests.md).
```

## CODE_REVIEW.md

Under the repository-specific checks:

```markdown
- **A change to the public contract** without a major changeset and a note in the commit message - blocker.
- **A dependency Medusa or the dashboard already brings**, declared again - major.
- **A migration file in the diff - blocker.** The one exception is a test module's migrations under
  `integration-tests/modules/`, generated by the user with `yarn test:db:generate` and committed with their
  `.snapshot-*.json`.
```
